# 相机—Franka外参标定现场步骤

## 标定目标

求解固定外部相机坐标到Franka基座坐标的刚体变换：

```text
p_base = R_base_camera @ p_camera + t_base_camera
```

当前程序支持“同一个刚性目标中心的三维点对应”法。正式精度评估优先使用固定在末端的
ChArUco/AprilTag刚性板；彩色点法可以先打通流程，但彩色目标必须刚性固定，不能用会在夹爪
中滑动的小球代替标定目标。

## 现场布置

1. 相机推车固定位置，锁住所有轮子，在地面标记三处轮子接触点和支架朝向。
2. 相机刚性连接支架，关闭自动移动；标定期间不得触碰推车、相机或镜头。
3. 避免让玻璃墙强反光进入深度工作区域；覆盖无关且ID重复的标定板。
4. 标记人员脚位和朝向。人员标定与机器人外参是两个独立步骤。
5. 确认急停可触及，机器人周围无人员；采集机器人姿态时使用低速和安全模式。

## 目标安装

- 目标必须刚性安装在末端法兰或已知TCP位置。
- 如果使用红色圆点/小球标记，记录目标中心相对TCP的固定偏移。
- 不要把贴纸随意贴在弧面，也不要把被夹持的绿色软球作为正式外参目标。
- 对每个姿态，相机记录的是目标中心 `camera_point_m`，机器人记录的是同一目标中心在
  `panda_link0` 中的 `robot_point_m`。

## 姿态采集

1. 先做一次静止深度检查，确认RGB与depth已经对齐，单位统一为米。
2. 采集15–20个姿态，覆盖后续球所在的三维工作区。
3. x、y、z三个方向都要有明显变化；不能只在桌面同一高度移动。
4. 每个姿态停稳后连续采集约30帧，使用中位数作为相机三维点。
5. 同时保存RGB截图、深度值、时间戳、机器人点和样本ID，禁止只抄最终数字。
6. 预留至少5个未参与求解的姿态作为独立验证点。

## 求解和验收

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m msc_cali.cli.solve_calibration `
  --input data\calibration_samples.jsonl `
  --output outputs\camera_to_robot.json `
  --max-rmse-m 0.020 `
  --max-error-m 0.040
```

初始流程门槛暂定RMSE不超过20 mm、单点最大误差不超过40 mm。论文或实际抓取应根据球尺寸、
夹爪容差和独立验证结果收紧门槛。不能只报告求解集误差，必须报告保留验证点误差。

## 球检测

球检测要求：

- 输入RGB数组通道顺序为RGB；
- 深度已经对齐到RGB像素；
- 深度单位为米；
- 使用ROI限制桌面区域，避免背景绿色物体；
- 用实拍图重新设定绿色目标色和容差。

当前相机已确认为Intel RealSense Depth Camera D435f。Windows端使用RealSense SDK 2.0的
`pyrealsense2`，初始配置为彩色与深度640×480、30 FPS，先丢弃30帧用于自动曝光稳定，
随后将depth对齐到RGB。保存文件中的RGB顺序固定为RGB，深度固定为米。

真实采集前先使用RealSense Viewer确认：

1. 设备名和序列号正确；
2. USB连接显示为USB 3而不是USB 2；
3. 彩色和深度流均能稳定达到30 FPS；
4. 深度在球和标定目标表面没有大面积空洞；
5. 固件升级只在Viewer验证稳定且实验室允许时进行，不在标定当天临时升级。

## 真机抓取启用条件

1. Franka Hand已经正确安装并能在Desk/ROS中单独测试；
2. 实测球直径、材质、质量和安全夹持力；
3. 外参通过独立验证点验收；
4. 目标点先只在RViz中显示，人工确认坐标方向和量级；
5. 添加预抓取点、桌面高度、工作空间、速度和碰撞限制；
6. 最后才允许机械臂运动。当前版本没有实现机械臂运动。
